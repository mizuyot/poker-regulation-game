## 姉妹作：ポーカー屋を作ろう！（v1.9）

5,000万円で営業スタイル・立地・卓数・内装・営業時間・料金・スタッフ教育の予算を決めてポーカー屋をつくり、最長5年経営する。期中は標準1倍速で自動進行し、1年は約36秒。営業中の速度は1/2倍・1倍・2倍・4倍から選べる。年次決算で翌年のニュースを受けて営業方針などを調整し、手元資金と営業区分に応じて融資を依頼できる。ニュースは1年適用し、同じニュースは1プレイ中に1回まで。

進行画面では前月の1日あたり来店客数と満席率、手元資金・事業価値を確認できる。枠の色はその時点の営業スタイルを表す。居心地・信頼の指標は廃止し、集客・常連化・売却査定の補正から外した。

年次決算での途中売却と、5年目の売却では、最終手取り額がスコアになる。売却額はDCF・類似取引比較・清算価値で評価する。黒・グレーの営業歴があればハコの価値で売却し、「売り抜け成功」で終了する。ゲーム内では換金ありが発覚すると賭博場開張で逮捕される。営業時間外・無許可・賞品提供などの風営法違反は、1プレイの初回に業務改善命令、2回目の発覚で逮捕される。逮捕時は違反営業中の累計利益の50%と借入残高を手元資金から差し引く。設計と検証の経緯は `docs/shop/DESIGN.md`。

公開ページ：https://mizuyot.github.io/poker-regulation-game/shop/ （GitHub Pages。全体ランキングはサーバーがないので使えず、この端末のランキングだけ）

```bash
python3 scripts/build_shop.py               # docs/shop/shop.json + 条文（questions.json）→ docs/shop/index.html と data/shop_rag.jsonl
python3 scripts/sim_v05.py                  # 立地×卓数ごとの手取り・倒産率（抽象モデル）
python3 scripts/sim_buyout.py               # 違法戦略が健全営業に勝てないかの検証
python3 server.py                           # http://127.0.0.1:8765/shop/
node scripts/sim_autoplay.js 16             # 実ゲームの自動プレイで釣り合いを測る（server.py 起動中に）
node scripts/sim_returns.js 40              # 戦略別の各年の手取り・累計・売却込みのトータルリターン
node scripts/sim_survival.js 40             # 立地×卓数の生き残り率と平均手取り（INTERIOR・EDU で内装と教育予算）
node scripts/sim_extremes.js 16             # 極端な設定での実験（エラー・NaNの検出）
node scripts/sim_score_reference.js         # 偏差値の基準となる256回の自動プレイを検証
python3 scripts/gen_layouts.py              # 卓数×内装の店舗レイアウトを shop.json に生成
```

### ローカルで遊ぶ

1. `python3 server.py` を起動する（Python 3.9以上、追加のライブラリは不要）
2. ブラウザで http://127.0.0.1:8765/shop/ を開く
3. 結果画面では最終手取り額・偏差値・成績分布・端末内ランキングを確認できる。成績は終了時に全国ランキングへ匿名で自動集計され、集計時点の順位が表示される。集計対象のプレイごとに、結果の種類・手取り額・立地・卓数・終了時の営業スタイルと区分・営業した月のスタイルの履歴・店のタイプ・抽選に使う内部値・ゲームのバージョン・集計時刻・再送の重複を防ぐプレイIDを `data/shop_scores.jsonl` に保存する。

全国・端末内ランキングは最終手取り額で並べる。全国順位は売却・逮捕で終えたプレイを対象とし、同額なら先に集計した記録を先に表示する。営業履歴には、営業した月のスタイルを期間ごとに並べる。履歴が保存されていない記録には「未記録」と表示する。

偏差値は `50 + 10 × (最終手取り額 − 基準の平均) ÷ 基準の母標準偏差`。基準は4地域で各64回、計256回の自動プレイ。5卓・「預入のみ、ゲーム内で完結」・シンプル＆モダン・17〜24時・基準料金・スタッフ教育月10万円で開業し、年次ニュースがある状態で設定を変えず、借入や追加出店をせずに進める。倒産した回の最終手取り額は0円とし、基準にも含める。

2号店の新規申請は休止中。申請済みのセーブでは、申請月から家賃が発生し、2か月後の開業から毎月、本店と同額の売上が加わる。新規申請を再開するには、`docs/shop/shop.json` の `expansion.branch.enabled` を `true` にして `python3 scripts/build_shop.py` を実行する。

`docs/shop/index.html` をファイルとして直接開いても遊べる。ファイルから開いた場合は、この端末のランキングを利用できる。

`/shop/?test=1` で営業中の時間を短縮し、決算画面を自動で進める（動作確認用。`&seed=7` で内部の乱数も固定）。

## データの置き場所

| ファイル | 役割 |
|---|---|
| `docs/questions.json` | 設問・選択肢・設計者の選択・解説・条文マスタ・バッジ定義の正本 |
| `data/answers.jsonl` | ローカル用の控え。公開ページでは回答を送信しない |
| `data/questions_rag.jsonl` | RAG投入用。`scripts/build_rag.py` で生成 |

公開ページでは、回答はこの端末内でのみ処理され、送信されません（集計版は準備中）。集計の仕組みを整えたうえで、分布を公開する予定です。ローカル起動時のみ、同一オリジンの `api/answers` に匿名ログ（セッションID・設問ID・選択肢・時刻）を残します。

Part 1 の設問IDは v5.2 で `q01`・`d4` を廃止し `d0` に統合した。v6.2 で `d0` を廃止し、形態の1段目 `p1` と2段目 `p2a` / `p2b` / `p2c` に置き換えた。過去の JSONL にある `q01` / `d4` / `d0` 行とは id が断絶する。
